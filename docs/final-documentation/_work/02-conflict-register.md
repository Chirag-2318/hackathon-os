## Reading rule

This register compares claims found in the existing documentation and process artifacts. The “code actually shows” column is based on targeted source inspection completed during this phase; the exhaustive code-truth pass in Phase 3 remains the final authority. “Newer by git date” compares the last committed dates of the cited paths, not the current uncommitted content. Confidence is about the current resolution, not about the historical document’s intent.

## Phase 2 conclusion

The strongest recurring failure mode is historical plan text being written as if it described the running product. The final set must use explicit status labels and cite current class/function/file paths. The largest unresolved verification areas carried into Phase 3 are the exact endpoint/DTO catalogue, exact generated document names, complete migration/schema reconciliation, production Compose versions, and current environment property names.
